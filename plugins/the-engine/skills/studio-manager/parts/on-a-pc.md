This is how each of those works on a PC. `<scripts>` here is the Assistant's `scripts` folder, beside this `parts` folder (also when the reel skill sent you here).

**Nothing here has been seen on a real PC yet (Nov 6, 2026).** It is written from Microsoft's and Python's documentation and from the scripts' Windows code, which has never run on Windows. ## Python, the PC's one missing piece

A PC comes with no Python. Windows answers `python3` with a line about the Microsoft Store ("Python was not found; run without arguments to install from the Microsoft Store..."), or opens the Store. That is not a problem. Say, in these words or close to them: "Before we start, your PC needs one free piece from Microsoft that I run on. Open the Microsoft Store, search for Python Install Manager, and click Get. Tell me when it's done and we'll pick up right here." Then stop and wait. Never send them to a terminal, a website or a download page. [Dustin and Nicole to decide: this is the smallest install the PC list found.]

**The Store puts in only Python's installer; Python itself comes down the first time anything runs it** (Python's own documentation: with nothing installed yet, the first `python`, `py` or `python3` downloads the newest Python, and the first install "will likely" ask whether to add a folder to PATH). That needs the internet and may take a minute or two [check on a PC: how long, and whether the question waits for an answer when you run it]. So on a PC the first Python command of every conversation is `python3 --version`, given a long wait (up to ten minutes) before calling it stuck, so that download never lands in the middle of a real step; when they have just installed it, say one line first ("Getting Python ready, one moment."). If that first run stops on a question, never answer it for them and never guess: say plainly that Python is asking something the first time it starts, and stop there [check on a PC].

If `python3` is still not found, try `py --version`, then `python --version`, and use whichever answers in place of `python3` in every command in these instructions, and in every command a script prints for you to run next. If none answers, ask them to quit Claude and open it again (a program that was already open may not see the new install yet) [check on a PC], then try again; still nothing, say so plainly and stop. Once one answers, carry on with what they first asked, as if nothing happened.

## What kind of computer, and what it can see

Once per conversation: `python3 "<scripts>/this_computer.py"`. It says Mac or PC, lists the drives by letter and any memory card, says where Pictures really is (Windows often keeps it in OneDrive), and which add-ons are there. It changes nothing.

## The words

Wherever a part says:

- "Mac" or "this Mac": say "PC" or "this PC". "Finder": "File Explorer". "The Dock": "the taskbar".
- Cmd: Ctrl (undo is Ctrl+Z, paste is Ctrl+V). The Option key (held so a drag copies instead of moving): Ctrl. Return: Enter.
- "The mic key" (dictation): "the Windows key and H". That is Windows' own voice typing; it needs the internet and the cursor in a text box. [check on a PC: whether it types into the Claude app's question boxes]
- A drive: its name and its letter, the way `studio_file.py drives` prints it: "Big Kahuna (E:)". A memory card often has a name like EOS_DIGITAL, or none ("Card (F:)").
- `~/.studio/`, the Assistant's own folder: on a PC it is the `.studio` folder in their user folder, `C:\Users\<their name>\.studio\`. The scripts find it themselves; never ask them to look in it. When a part has you read a file in it yourself (`~/.studio/posting-url.txt`, `~/.studio/queue-url.txt`), use its full path: `python3 -c "import pathlib; print(pathlib.Path.home())"` prints their user folder once per conversation, and the file is in `.studio` inside it. Never write it as `%USERPROFILE%` (only the old Command Prompt reads that), and never hand a script a path that starts with `~` on a PC (the PowerShell every PC has passes the `~` on as it is).

## Commands

Every command in the parts is written the way a Mac's command line reads it. On a PC your commands run in PowerShell or in Git Bash, depending on what is installed; quote for the one you are using. Either way:

- **Double quotes around every path, and around anything with a comma in it** (`"s1=14,3,27,9,41,18"`, `--reel "7,2,11+,4,9-"`). PowerShell cuts a bare comma list into pieces. The scripts folder is in their user folder, and a user folder often has a space in it ("C:\Users\Jane Doe"), so `"<scripts>/night.py"` always goes in quotes too.
- **Quotes around everything that came from them, even one plain word:** a name, a shoot name, an Instagram handle, a caption, what they said. In PowerShell a bare word that starts with `@`, `$`, `#` or a bracket means something else: `--handle @horizonfound` hands the script nothing at all. In PowerShell these go in single quotes (see "What they said" below): `--handle '@horizonfound'`.
- **A path never ends in a backslash inside quotes.** A backslash right before the closing quote swallows the quote. Write a card or a drive as `"E:/"`, never `"E:\"`, and never a bare `E:` (Python reads a bare `E:` as "wherever I last was on drive E", not the top of it). Forward slashes work in any path on a PC. So the card from `studio_file.py cards` (`E:\   EOS_DIGITAL (E:)`) goes in as `--source "E:/"`, the same way every time.
- **One command per call.** No `&&` between commands (the PowerShell every PC has refuses it) and no `\` at the end of a line to carry a long command onto the next: write it on one line.
- **What they said about a card** ("What's on the card?"): write it word for word to a text file with your file-writing tool (for example `said.txt` in their `.studio` folder), then `client_note.py told --night "<backup>" --text-file "<that file>"`. It never passes through the command line, so nothing in it can change on the way. The same for what they say about a shoot for its post kit (`parts/post-kit.md`): write it to a file, then `kit.py told "<kit>" --text-file "<that file>"`. [check on a PC]
- **Anything else of theirs, word for word** (`rename_shoot.py --name`, `posting_queue.py feed --handle`): in PowerShell, put it in single quotes, because inside double quotes PowerShell reads `$` and the backtick as instructions and the words would change. Inside the single quotes, double every apostrophe, straight or curly (`'Sarah''s twins turn two'`): PowerShell counts both kinds as quote marks. Write any straight double quotes in what they said as curly ones (“ ”): straight ones can be lost on the way into a script on a PC, and curly ones keep the words the same. [check on a PC] In Git Bash, quote as on a Mac.
- **A list for a script** (Canva's download links for `canva_kit.py fetch --urls`): save the list to a file and pass the file's path. The script takes either; on a PC the quotes inside a list can be stripped on the way in.
- **Opening an address in the default browser** (only ever where there is no browser pane, outside the Claude app): `python3 -m webbrowser "<address>"` where a part says `open` it.

## Pictures: one more free add-on

On a Mac, previews, contact sheets and sneak peeks are made with the Mac's own picture tool. A PC has none, so there they need one free add-on called Pillow. For camera RAW files the Assistant uses the small JPEG every camera tucks inside the RAW (what the back of the camera shows); the RAW itself is only ever read. Before the first backup, drop, post kit or reel in a conversation, run `python3 "<scripts>/pictures.py"`:

- "Small pictures are made with: Pillow": carry on. (The backup's preflight, `night.py --check`, says the same thing as a STOP when the add-on is missing: answer it the same way, below.)
- It says the add-on is missing: say, in these words or close to them, "Your PC needs one more free piece before I can show you your photos. It's called Pillow, and I can add it now. It takes about a minute. OK?" [Yes, add it (recommended)] [Not now]. On yes, run `python3 -m pip install pillow` (with the name for Python that answered above), then `pictures.py` again, and carry on. On "Not now", or if the install fails or pip itself is missing: say in one plain line that photos can't be shown on this PC until it is added, and stop there. Never download anything else, and never work around it. [Dustin and Nicole to decide: the Assistant adds it on a yes, as here, or the setup guide has them do it.] [check on a PC: whether the Store's Python comes with pip, and whether Auto lets the install run without asking]

## The backup

- **Finding the card:** `studio_file.py cards`, the same command as on a Mac; it lists the card by its letter. Use it as `--source "E:/"` (see Commands).
- **The drive question:** the computer's own disk is usually C:, and `studio_file.py drives` already leaves it out. Time Machine is a Mac thing; on a PC, leave out a drive that File History or other backup software uses (a `FileHistory` folder at the top is the tell).
- **Drive letters move, so check them before every backup. This one keeps the card safe.** On a PC the Studio File keeps the photo drive by its letter (`E:\`, or `E:\Photo Shoots`), and Windows hands out letters as things are plugged in, so another day the card can get the letter the photo drive had. On a Mac the drive's name is in its path, so this never comes up there.
  - **At setup,** `studio_file.py set --drive` (and `--second`) also keeps which drive that letter is: its name and the drive's own number, read from Windows. `studio_file.py show` then prints it as "Sessions go on: `E:\` (Big Kahuna)". Nothing more to save. [check on a PC]
  - **Every backup, before the one-screen check-in and before the preflight** (`night.py --check` writes a small test file on the drive it was given, so it must never run until this is done): run `studio_file.py show` (the saved drive, with its name), `studio_file.py cards` and `studio_file.py drives`. Go on only when the card's letter is not the saved drive's letter (nor the second copy's), and the drive at each saved letter today is the one named beside it. Then the check-in names it with its letter: "Onto Big Kahuna (E:) like usual?" The backup checks this itself too: when the usual drive's letter holds a different drive today, `night.py` (and `--check`) stops before writing anything, with "Windows gave your drives different letters today: Big Kahuna is F: now, and E: is the memory card today. I won't start until we're sure where your photos are going." [check on a PC]
  - **If either is off, never start the backup, and never guess which letter is which.** Say it plainly: "Windows gave your drives different letters today: Big Kahuna is F: now, and E: is the memory card. I won't start until we're sure where your photos are going." Then ask: [Back up onto Big Kahuna (F:) this time] [I'll sort the drives out first]. [Dustin and Nicole to decide: what to offer here, and which one is recommended.] On the first, run this backup with `--dest` at the drive's new letter (and the same folder on it, if the Studio File has one: `--dest "F:/Photo Shoots"`) and `--second` the same way, for this backup only, as "Somewhere else this time" in `parts/backup.md`; the Studio File stays as it is. If the drive named beside the letter isn't plugged in at all, say so and wait, as on a Mac.
  - **A Studio File with no name beside the drive's letter** (set up before Nov 6, or with an older note such as "Shoots drive: Big Kahuna (E:)" instead): before the check-in, make sure the card is not on the saved drive's letter, ask once with the name and letter from today's `studio_file.py drives` ("Onto Big Kahuna (E:) like usual?"), and on yes run `studio_file.py set --drive` again with the same saved path, written with forward slashes (`--drive "E:/Photo Shoots"`; `--second` the same way), so it keeps the drive's name and number from now on.
- **A drive that seems to be unplugged but isn't.** Every record, queue entry and settled shoot keeps its folder by letter (`E:\...`). When a script or a page says to plug in "the drive that was E:", or the preflight says "The drive is not plugged in", run `studio_file.py drives` before asking them to plug anything in. If the drive the Studio File's note names is there under a new letter, say so instead: "Big Kahuna is plugged in, but Windows gave it a new letter today, F:." Opening older shoots from the pages, and anything else that goes back to an earlier backup, may not find their folders until it has its old letter again [check on a PC]. Unplugging the card and the other drives, then plugging Big Kahuna back in, usually gives it its old letter [check on a PC]. Never edit a record to point at the new letter.
- **Staying awake:** the backup asks the PC not to sleep while it works [check on a PC]. A closed laptop lid still sleeps it, as on a Mac: leave it open and plugged in. If a backup stops because the PC slept, run the same command again; nothing is copied twice.
- **A rename, a sort or the settle stops saying "Something has a photo in this folder open"** (the scripts' own words for it), **or with "Access is denied", "being used by another process" or a PermissionError.** Windows won't rename or move a folder while another program has one of its files open: Lightroom, a File Explorer window showing that folder, the Photos app, sometimes the virus checker reading a file just written. A Mac never does this. Nothing is lost: each of those steps writes its log before it moves anything, and running the same command again finishes what it started (as on a Mac; never yet seen on a PC). Say: "Windows wouldn't let me move the beach shoot's folder while another program has a photo in it open. Close Lightroom and any File Explorer window showing that folder, then say go." On "go", run the same command again. Never move or rename anything by hand to get past it.
- **A photo's place too long for File Explorer.** Windows' File Explorer can't open a file whose whole place (the drive, every folder on the way, and its name) is over 260 characters, even where long paths are switched on, so the Assistant never makes one for a photo. Nothing moves when it would:
  - The backup stops at the sort with "a photo's new place would be longer than File Explorer can open (260 characters, counting the drive and every folder on the way). A shorter name for the shoot fixes it." and a "too long:" line naming the place. Nothing moved. Offer a shorter name for the shoot in that line; then write it as that shoot's `"suggested"` in the backup's `_studio/shoots.json` and run `night.py` again.
  - The settle says "Left together, on purpose: a photo's new place would be longer than this PC allows..." (the shoots stay safe in the day folder; the backup otherwise finishes). Offer a shorter name, rename the shoot with it (`parts/after-the-report.md`), then run the same `night.py` command again to put the shoots in place.
  - A rename stops with "STOP: the new name would make a photo's place longer than File Explorer can open ... Nothing renamed. A shorter name fixes it.": ask for a shorter name.
  If their drive's folders are already deep (a long path to where their shoots go), say so plainly; never move anything by hand.
- **Hidden folders:** the Assistant marks its own folders hidden (`_studio`, `.studio`, a post kit's `.kit`). Someone with "Hidden items" switched on in File Explorer sees them, faded. They are the Assistant's own; ask them to leave them as they are.
